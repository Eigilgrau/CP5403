| Merged episode median durations are approximately 210 minutes for RuntimeExcessive and 30 minutes for SupplyTempTooCold. | Counting every tick would give longer events disproportionate influence. Sample each positive episode once. |
| The initial sample has 3,313 non-overlapping windows. A 0.75 component-fraction rule retains 3,308, removing five controls and retaining every sampled positive. | Use 0.75 for this pilot. The sensitivity table provides the cost of alternative thresholds. |

The predictive folds repeat this screening independently. |

| All 25 penalised diagnostic fits converge. The main linear model's mean check-fold macro-F1 is 0.536. | The pipeline is computationally usable, and the diagnostics reveal meaningful classification limitations. |

## Code Flow and Responsibilities

The notebook owns the narrative, plots, analysis queries, and publication step. [phm_case_design.py](../phm_case_design.py) contains the reusable sampling, aggregation, transformation, and validation functions. It imports the previously verified `summarise_window` function from [phm_case_samples.py](../phm_case_samples.py), together with the clock and target constants from [phm_preprocessing.py](../phm_preprocessing.py).

### 1. Restrict the Analysis to Training Sites

`attach_training_views` attaches the prepared source database read-only and creates temporary views of its component bins, decisions, episodes, and inventory. Each view joins to the saved site manifest and filters to `train`. A count check verifies the 46-site cohort.

The notebook's support tables distinguish ticks, episodes, and sites. Its channel audit computes exact extrema, null counts, and distinct-value counts, with streaming approximate quantiles for the large measurement table. Site-level medians are also approximate. This keeps the scan inside the 256 MB DuckDB managed-memory budget. The small per-case window statistics use exact calculations.

### 2. Scout Candidate Decision Points

`select_scout_points` reads one site's eligible clock at a time. For each target episode, the NumPy generator seeded with `5403 + site_id` chooses one of its eligible ticks. Eligible controls form their own shuffled pool. The class visitation order is also seeded.

The selector visits class pools in round-robin order. It accepts a candidate when its decision time is at least three hours from every accepted time at that site. A sorted list and neighbouring-time checks avoid a quadratic comparison with all accepted windows. A site contributes at most 30 points per class. The function records accepted points, overlap rejections, and candidates left unvisited after reaching the cap.

If an episode's selected tick overlaps an accepted case, that episode loses its sampling opportunity. The pilot does not search for an alternative time in that episode. Sampling before the later coverage filter also means a rejected low-coverage point is not refilled. These choices are explicit in the saved contract.

### 3. Compute the Case Summaries

`aggregate_scout_points` joins selected windows to the component-bin table one site at a time. It materialises only the selected rows, then calls the established component-first summary function. It independently checks each retained observation against the open-left, closed-right trailing window.

For each channel, a component contributes when at least eight of twelve bins contain values. Its median, IQR, and last-minus-first change are summarised across qualifying components using the median, lowest, and highest value. Supplementary features include the median of component means, sample standard deviations, minima, maxima, and ranges. Standard deviation uses `ddof=1`.

The first-channel coverage measures are defined as follows.

| Metric | Calculation | Interpretation |
| --- | --- | --- |
| `usable_component_fraction` | Components meeting the eight-bin rule divided by components observed in the three-hour window | Whether most observed components can contribute a summary |
| `recent_component_fraction` | Components observed in the window divided by distinct components observed in the preceding 24 hours | A causal check for recently observed units disappearing |
| `bin_coverage` | Populated first-channel component bins divided by twelve times the observed component count | How much of the measurement grid is populated |

The 24-hour roster uses observations available at the decision. A component absent for longer than a day can disappear from that denominator. Newly appearing components and partial records near a site's start can also affect the roster. The notebook documents this limitation.

Occupied and setback proportions use all observed component bins in the window. The source state strings occur across all training sites. These proportions retain their literal source-label interpretation.

### 4. Apply and Inspect the Pilot Coverage Rule

`coverage_sensitivity` compares thresholds of 0.00, 0.50, 0.75, 0.90, and 1.00 for both component fractions. The notebook displays retained cases and represented sites per class. The final scouting table uses 0.75.

The retained cohort contains 1,375 controls, 1,088 RuntimeExcessive cases, and 845 SupplyTempTooCold cases. It covers all 46 training sites. Each positive episode appears once at most. All windows within a site are separated by at least three hours.

The feature matrix is saved with opaque case IDs. A private table holds site, decision time, episode, outcome, window boundaries, actual observation boundaries, and recent component counts. The score and feature tables can be paired by case ID during later analysis.

### 5. Assess Feature and Statistical Suitability

The EDA compares class distributions, redundant feature pairs, supplementary means and standard deviations, within-site dependence, constants, missingness, matrix rank, and conditioning. Pairwise empirical target/control log-odds curves provide a visual screen for curved relationships.

The main model begins with 25 candidate predictors. Twenty describe channels 1, 2, 4, and 5, using the typical component median, typical IQR, typical change, lowest component median, and highest component median. Three describe coverage, and two describe operating state. The full set of seven channels and supplementary statistics remains in the case-feature table.

Predictor normality is not required by logistic regression. Independence and correct predictor effects on the relevant log-odds require more careful assessment. Here the design addresses overlapping windows and grouped evaluation, while residual site clustering and the curved-response findings remain limitations. The notebook includes the primary methodological references and records each condition in `assumption_audit`.

### 6. Fit the Diagnostic Models Inside Site Folds

`run_diagnostics` assigns cases to five `GroupKFold` folds using `site_id`. Every variant uses the same fold membership. Assertions verify that fit and check sites are disjoint and that each side contains all three classes.

`FoldTransform` learns its parameters from the fitting cases. Optional clipping uses the 0.5th and 99.5th percentiles of each feature. Median imputation follows, then constant removal and a greedy absolute-Spearman screen at 0.95. Declared feature order decides which member of a redundant pair is retained. Standard scaling follows the transformation. The fitted multinomial model uses L2 regularisation, `C=1`, `class_weight='balanced'`, and the L-BFGS solver.

| Variant | Representation | Mean macro-F1 | Fold SD | Mean log loss |
| --- | --- | ---: | ---: | ---: |
| `coverage_only` | Three coverage measures | 0.287 | 0.053 | 1.098 |
| `linear` | Main candidate feature set | 0.536 | 0.025 | 1.038 |
| `all_numeric` | Adds channel 3, 6, and 7 summaries | 0.566 | 0.045 | 0.996 |
| `clipped_linear` | Main features with fitting-fold tail clipping | 0.540 | 0.028 | 0.933 |
| `clipped_spline` | Clipped main features with curved additive effects | 0.612 | 0.036 | 0.870 |

The spline transformer uses four quantile knots and cubic terms, with linear extrapolation outside the fitted range. Fixed C across representations means basis size and regularisation also influence this comparison. The mean fit-fold macro-F1 rises to about 0.702 for the spline variant, compared with 0.612 in check folds. This gap remains relevant when considering model capacity.

The optional site-averaged macro-F1 in `fold_metrics` uses the same three-class label set at every site and assigns zero to undefined class F1 values. Some sites lack a sampled class, so this statistic answers a stricter question than pooled macro-F1. The notebook focuses on pooled fold scores and shows site support separately.

### 7. Link Model Parameters to Case Metrics

The logistic coefficients and intercepts are shared by cases evaluated with the same fitted model. The saved parameter table identifies their fold and class. The preprocessing table records the input feature, retained column position, imputation median, scaling mean, and scaling standard deviation.

For the linear pilot, each standardised feature is multiplied by its class-specific coefficient. Adding the class intercept gives the linear predictor. Softmax of all three predictors gives the case's scores. The notebook saves these term contributions for one example and reconstructs the stored scores numerically.

`oof_scores` contains one prediction per case and diagnostic variant, together with the fold, model ID, three scores, predicted label, and the gap between the two largest scores. Each score comes from a model fitted on other training sites. The class-balancing scheme and deliberately sampled cohort affect score interpretation. Reliability curves describe this cohort, and operational calibration remains unresolved.

## Handoff to the Final Case Set

The case-selection and aggregation functions are ready to reuse with the recorded clock, episode, spacing, and coverage rules. The present cohort supports development and design inspection. The 30-case site/class cap sets the size of this scouting exercise. Final cohort counts should be chosen explicitly for the planned evaluation.

Carry the basic summaries and coverage into case records. Join out-of-fold scores by case ID for training diagnostics and historical examples. For a future validation or test query, the fitted training model supplies its scores through that model's saved transformation. Keep the private reference outcome separate from the model-facing measurements.

The observed spline improvement supports checking a curved representation during validation. Its gain does not establish that the main linear model satisfies the log-odds assumption. Channel encoding, incomplete event recording, site clustering, and sampling-dependent score calibration also remain part of the classification limits. The notebook's evidence supports a transparent baseline and a focused next comparison before freezing the full experiment.
