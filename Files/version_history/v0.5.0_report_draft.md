## Implementation Basis and Data Flow

The completed-method account is based on `Files/preprocessing_experimental_data.ipynb`, `Files/eda_case_design.ipynb`, `Files/case_representation_and_retrieval.ipynb`, the reusable numerical implementation and saved `Datasets/PHM15-prepared/case_system.duckdb`, together with histories v0.1 through v0.3. This report task does not rerun preprocessing, fit another model or construct final test cases.

The flow starts with 66 eligible sites, separated into 46 training, ten validation and ten reserved test sites. Three-hour windows on a fifteen-minute grid become eligible cases after coverage and label checks. There are 3,308 training cases and 728 validation cases; the report gives their class counts. Training-only preprocessing supports 31 retained descriptors and the selected 127-coordinate-per-class temporal-spline classifier. Coefficients are shared model parameters; scores belong to individual cases. Historical scores use whole-site out-of-fold fitting.

Numerical retrieval searches training cases using group-balanced descriptors and returns three neighbours from different sites. Query outcomes are private evaluation data, not retrieval inputs. Native values, preparation flags, class scores and known historical outcomes are assembled into a JSON-compatible record. This interface can feed a future LLM pipeline without requiring text embeddings of the numerical cases. Literature passages will have a separate retrieval and provenance process.

The methodology describes predictive safeguards rather than asserting all classical inferential assumptions are satisfied. Logistic regression does not require normal predictor distributions. Site dependence, representation choice, redundancy, calibration limits and prior validation selection remain explicit.

## Proposed Evaluation Decisions

The draft uses four conditions: A is the fitted logistic model; B is the LLM with numerical features and logistic scores but no retrieval; C adds historical cases; D adds literature. B is therefore a no-retrieval baseline with numerical assistance. Keeping query evidence and generator settings fixed makes B versus C and C versus D interpretable. An optional additional comparison broadens PHM-specific literature with external domain sources under equal context budgets.

A ten-query validation pilot and approximately 90 test cases are proposals, not completed runs or final guarantees. The draft proposes 12 human-reviewed test cases across B to D, yielding 36 explanations. Sample selection and pipeline settings must be fixed before examining generated test outcomes. Test labels remain evaluator-only information except when used by the sampling and scoring procedure.

Macro-F1 is the primary classification measure, with per-class precision, recall and F1, accuracy and confusion matrices. Invalid and abstained responses remain failures in the classification denominator. Case hit at three is explicitly a label-overlap proxy. Explanation checks separate numerical agreement, supported claims, unsupported or contradicted claims, and citation validity, precision and completeness. Llama judging is conditional on runtime feasibility and agreement with human review; it does not replace label-based scoring. Runtime and token costs are logged separately for diagnosis and judging.
