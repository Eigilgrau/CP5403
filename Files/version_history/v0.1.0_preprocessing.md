## Code Flow

### 1. Audit the Source Files

`inventory_sites` visits sites 1 through 70 in numerical order. It records file status and byte size for the component (`a`), zone (`b`), and event (`c`) streams. A site's inclusion depends on usable component readings, valid log intervals, and eligible clock ticks. Zone availability is an inventory field. Zone signals need their own validation, including the original challenge's cumulative-energy rule, before feature use.

`ingest_components` reads one headerless component file at a time. Its ten fields are the component ID, timestamp, seven numeric channels, and a categorical operating state. The timestamp retains the local clock written in the file. Empty fields and the source marker `\N` are missing. Unparseable or non-finite numeric tokens become null and are counted separately from ordinary missing values. A missing component ID or unusable timestamp prevents bin placement. Structurally malformed records go into `component_rejects` with the original text and physical file line.

The audit reconciles **source records = malformed records + invalid keys + superseded readings + retained bins**. Superseded includes both duplicate measurements and valid updates within a quarter hour. This count alone does not establish how many exact duplicate source rows exist.

### 2. Place Measurements on the Clock

`ingest_components` assigns each valid reading to the first quarter hour at or after its actual timestamp. Within a component and bin it sorts by actual timestamp descending and then by parsed source-record order descending. Keeping the first row gives deterministic ties even for an unsorted file. The row's channels, timestamp, and state travel together. A later row with a missing channel leaves that channel missing.

`component_bins` stores observed bins only. Channel IDs `ch1` through `ch7` refer to CSV fields 3 through 9 in order. The local file gives no physical units for these values. Keeping the native scale preserves unusual readings for inspection. The categorical state is retained as provenance for future encoding checks.

### 3. Separate Logged Events From Measurement Evidence

`ingest_events` reads all event names. Each interval receives a quality code. `merge_episodes` selects valid intervals of the two targets and orders them by site, event name, start, and end. It compares each start with the **largest prior end**. This handles a short interval nested inside a long one. Identical or overlapping intervals collapse into one episode with a count of contributing rows. Adjacent intervals remain separate at their shared boundary.

A decision belongs to an episode when `start_at <= decision_time < end_at`. A valid short event can contain a quarter-hour tick. Its timing determines whether it is available. The `hits_clock_grid` flag records this before applying measurement or logging checks.

### 4. Record Eligible and Excluded Decisions

`prepare_decisions` constructs one site's quarter-hour clock within its first and last observed component timestamps. For each component, `coverage_on_grid` places its populated first-channel bins on this clock. A difference of cumulative counts calculates the number present in the last twelve bins. A component contributes to `usable_ch1` when that count reaches eight. Missing bins contribute zero observations. Missing sensor values stay null.

The pilot needs three hours of recorded history and at least one qualifying component on `ch1`. For several simultaneous exclusion conditions the first matching reason below owns the tick. This makes the exclusion counts additive.

1. An unresolved target with a known start censors all later decisions at that site. A target with an unusable start prevents the site from entering the scoring clock.
2. Two active targets make the reference label ambiguous.
3. A prospective control during a recorded `NOCOMMS` outage is excluded. An outage without a valid end extends through the remaining clock.
4. A prospective control needs valid log starts on both sides, each no more than seven days away. A single entry exactly at the decision cannot supply either side.
5. A lookback extending before the first measurement is incomplete.
6. Zero qualifying components makes first-channel coverage insufficient.

An eligible tick gets one target name or `NoRecordedTarget`. Other event names may be active for that last class. The local challenge rules warn of omitted events in original test records. The named-site release provides no verified map of those incomplete periods. Bracketing documents recent logging activity and cannot certify equipment health. See the [local challenge rules, pp. 3–4](../../Datasets/PHM15-master/PHM_Data_Challenge_Rules_2015_Repository.pdf).

### 5. Freeze the Site Manifest

`freeze_split` removes sites that have no eligible decisions, reserves Site 1 for development, and shuffles the remaining numerically sorted IDs with seed `5403`. It reserves approximately 15% each for validation and testing. The remainder joins Site 1 in training. The saved `site_split` table is the assignment to reuse. The notebook checks site uniqueness and class availability across splits.

### 6. Build a Measurement Query and Its Private Score

`build_sample` includes the guide's Site 1 decision and selects the earliest eligible tick of the requested class at each additional seeded training site. The sample contains three examples per class from nine distinct sites. This small, deliberately balanced sample illustrates the data contract. It does not estimate class prevalence.

`read_window` obtains only rows with `t - 3 hours < bin_end <= t` and verifies the actual observation times too. `summarise_window` works one channel at a time. Each component with at least eight valid bins contributes its median, interquartile range (linearly interpolated 75th minus 25th percentile), and last minus first valid value in time order. For each statistic, the query reports the median, lowest, and highest value across qualifying components. An empty set of qualifying components produces null summaries. Coverage reports observed components, usable components per channel, and populated versus possible bins. The denominator is twelve times the number of components observed anywhere in the window.

Each query has a reproducible opaque ID derived from its site and time. The private scoring row carries that ID, site, split, decision time, window bounds, actual observation bounds, eligible outcome, and merged episode ID where applicable. `private_training_index` restricts sample membership using the manifest. Retrieve the feature vector from `sample_queries` by its case ID.

## Handoff to Case Construction

Use `private_decisions` filtered by `status='eligible'` and join to `site_split` by `site_id`. Choose at most one decision per positive `episode_id`. Space controls and avoid overlapping held-out windows within a site. Neighbouring ticks can describe the same episode and share nearly all their measurements.

After selecting a site and its aligned decision time, these two calls produce its feature dictionary in a notebook cell with an open database connection.

```python
window = samples.read_window(db, site_id, decision_time)
features = samples.summarise_window(window)
```

Fit imputation, scaling, reference percentiles, and the classifier on training cases. The nine examples validate the interface for that next step. Store any final label, split, and absolute time on the private scoring side. Review training-site coverage and unresolved periods before fixing the final sampling threshold.
