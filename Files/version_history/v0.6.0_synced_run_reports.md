# v0.6.0 — Synced run reports and C/D-only scope

This revision follows the user's instruction to simplify the main diagnostic ablation to C and D and to make Colab outputs reviewable through Google Drive desktop. It supersedes the A–D planning language in earlier notes. The DOCX drafts and historical revision notes were not rewritten.

## Changes

- Added `experiment_config.json`, consumed by notebook/report setup, with C and D as the only permitted conditions. Both retain numerical features, regression scores and identical historical cases. D adds literature. The configuration guard rejects additional arms or disabled pairing controls.
- Added `phm_run_reporting.py`, using the standard library for logging. Run IDs preserve separate histories; `Outputs/LATEST_RUN.md` and its JSON pointer identify the latest update. Reports include package versions, configuration snapshots, checks, progress, exceptions, file fingerprints and structured literature status.
- Added setup and final reporting cells to all four existing notebooks. They accept an explicit project root, including a mounted Drive folder. Numerical calculations and their existing environment requirements are preserved. Existing numerical cell outputs remain historical until those notebooks are rerun.
- Connected Qwen request checkpoints and model/setup failures to the reporter. Per-request response caches remain the resume mechanism. Cached raw outputs, validated boundaries, rejected proposals and requests that have not run remain distinct.
- Added small saved-database exports for numerical notebook review. They inspect existing contracts and aggregate development metrics without unpickling or refitting models.
- Updated the current project guide to C/D, paired cost calculations, two explanations per audited case and stage-based checkpoints. Added `COLAB_RUN_GUIDE.md` with the sync workflow and file list.
- Corrected the literature notebook's inspection check to validate the selected document's chunks against that document's source units when multiple papers are present.

## Boundaries

Reporting starts after a writable project directory is selected. Drive-mount and missing-project-path errors remain visible in Colab because a synced report location is not yet available. A killed runtime can leave a report marked `running`; the last event and saved request caches are the recovery evidence. Logs capture text and tracebacks rather than every rich notebook display; selected machine-readable results are exported separately.

The active configuration is a contract for the forthcoming diagnostic runner. This revision does not implement literature vector retrieval, portable case-evidence export, diagnostic prompting or final C/D evaluation. It does not guarantee cross-version portability of the existing fitted scikit-learn payload. Use the numerical foundation already prepared and add the remaining stages incrementally.
