## The Representation Decision

Each case has three useful numerical forms.

| Form | Contents | Consumer |
| --- | --- | --- |
| Native descriptors | Component levels, extremes, variation, temporal contrasts, slopes, persistence, and coverage | Human review and evidence generation |
| Prepared classifier coordinates | Training-fitted clipping, imputation, redundancy removal, spline expansion where applicable, and scaling | Multinomial logistic regression |
| Retrieval vector | Retained descriptors before spline expansion, standardised and weighted by feature group | Historical-case search |

The native descriptor table preserves interpretability. A classifier can use curved functions of those descriptors, and retrieval can compare their numerical patterns directly. Model coefficients are shared across queries using that fitted model. A query receives its own scores when its prepared coordinates are combined with those coefficients.

The declared rule selects **temporal spline**. Its macro-F1 improves by approximately 0.071 over the summary-only linear model on the same cases. The selected model retains **31 base descriptors** and expands to **127 classifier coordinates per class**. Its three coefficient arrays and intercepts apply to those prepared coordinates. The stored model reproduces their clipping, imputation, feature order, spline basis, and scaling.

## Code Flow

### 1. Reuse the Case Contract

The notebook writes `selection_protocol` before extracting validation outcomes. All six candidates use the same cases, clipping percentiles, L2 regularisation with `C=1`, class-balancing policy, and redundancy threshold.

The training feature table comes from the retained v0.2 cohort. The existing sampling and aggregation functions now accept an optional `prefix` argument. This allows explicit `validation` views to reuse the same logic. The default uses the training views, preserving the earlier notebook's behaviour.

The notebook applies the same quality filter after sampling and spacing. Rejected low-coverage cases reduce the sample rather than triggering replacements. The audit records these counts.

### 2. Extend the Window Descriptors

`augment_points` retrieves the selected windows in site batches and passes each to `extended_window`. The latter converts the small window to numerical arrays and groups by component. This avoids repeated per-component dataframe construction. DuckDB uses one execution thread and a 256 MiB database memory limit; Python and numerical-library memory are additional. The full measurement table is never converted into a dataframe. The completed model and historical-bank artifact is approximately 7.5 MiB.

For channels 1, 2, and 5, each qualifying component contributes the following.

| Descriptor | Definition |
| --- | --- |
| Recent median | Median of readings in the final four quarter-hour bins, requiring at least two valid bins |
| Recent component extremes | Lowest and highest recent median across qualifying components |
| Early-to-recent change | Final-hour median minus first-hour median, with at least two valid bins in each hour |
| Slope | Least-squares change in channel value per elapsed hour, using actual timestamps across at least eight bins |

The site-level trend descriptors use medians across components. Recent component coverage is also retained. Slope here describes a signal's trajectory within a case. The logistic model's coefficients describe the fitted relationship between case descriptors and the recorded classes.

For channel 3, the transition rate counts changes between observed adjacent bins and divides by the number of such adjacent pairs. The longest same-code run resets across missing bins and is divided by twelve possible bins. These measures describe switching and persistence through code equality.

The categorical sensitivity builds within-component code-frequency profiles for channels 3, 6, and 7, requiring eight observations per contributing component. It averages components equally. `CaseEncoder` learns up to five common categories from its fitting cases, omits the most frequent reference category, and pools other values. This includes a defined treatment of future values outside the fitted vocabulary.

### 3. Learn the Transformation

`CaseEncoder` chooses the feature families for the declared candidate. `NamedPreparation` reuses the established `FoldTransform` and preserves the selected column names.

The transformation clips at training 0.5th and 99.5th percentiles, imputes training medians, removes constants, and greedily removes pairs with absolute Spearman correlation at least 0.95. The declared feature order decides which member survives.

`CurvedFeatures` creates cubic spline terms with four quantile knots for sufficiently varying continuous descriptors. Fractions, coverage, and transition rates keep their direct coordinates. Extrapolation beyond the fitted spline range is constant. `StandardScaler` then scales the classifier coordinates.

The multinomial logistic model uses L2 regularisation, `C=1`, `class_weight='balanced'`, and L-BFGS with a convergence check. The six candidates are evaluated once under the declared rule. Candidates within 0.005 of the best macro-F1 prefer fewer coefficients, then lower log loss.

### 4. Build Historical Scores and the Bank

`cross_fitted_scores` fits the selected representation on five whole-site folds within training. Each historical case receives one score vector from a model fitted on other training sites. These diagnostic scores are retained with fold and model IDs.

`CaseSystem` receives the classifier fitted to all training cases and the same historical cohort. It checks that the bank's case IDs match the model's recorded training IDs and that every historical case has one out-of-fold score.

The bank stores its retained native descriptors, training-only retrieval scaling, numerical vectors, and private provenance. The fitted classifier supplies scores for new queries. Outcome labels are used when displaying historical evidence and when evaluating retrieval.

### 5. Retrieve Comparable Cases

The search operates on retained descriptors before spline expansion. After standardisation, a feature's weight is

`1 / sqrt(features_in_its_group * number_of_groups)`.

Euclidean distance therefore balances the average squared differences of channel, coverage, and operating-state groups. This prevents a group with many descriptors from dominating through its column count alone.

The query's own case is excluded. Supplying the site excludes all historical cases from that site. A known historical query ID also allows the site to be inferred for this exclusion. Returned neighbours come from distinct training sites. If the request exceeds the available eligible sites, the result remains shorter rather than admitting an excluded site; an oversized-request sanity check verifies this boundary.

The three nearest neighbours contain at least one matching recorded label for approximately **83.2%** of validation queries. By class, the fractions are approximately 83.6% for controls, 90.9% for RuntimeExcessive, and 76.9% for SupplyTempTooCold. A simple majority vote, breaking ties by nearest-neighbour order, reaches macro-F1 **0.584**.

The matching-label fraction is a retrieval proxy. A matching outcome does not establish that a particular explanation is supported. Each returned record therefore includes native feature values, one close numerical feature, and a feature with a large standardised difference.

### 6. Create a Query From Measurements

`query_from_measurements` takes a prepared component database, site ID, and a timezone-naive quarter-hour timestamp on the dataset clock. It checks the available history, loads the trailing window and prior 24-hour component roster, applies the coverage thresholds, and computes the same descriptors.

The function uses the component table. A missing or inadequate window returns a reason. A usable window returns a feature dataframe with an opaque case ID.

`CaseSystem.evidence` converts that dataframe into a record containing native feature values, measurement quality, preparation flags, class scores, model ID, and three historical analogues. Query site IDs, absolute timestamps, episode boundaries, split membership, and private reference outcomes stay outside the evidence record.

Clipping and imputation are listed explicitly. A displayed standardised comparison uses prepared values, while its displayed raw values preserve the original feature magnitudes.

## Calling the Saved System

Run the following from the project `Files` directory in its Python environment. The timestamp is the guide's Site 1 development example. The historical search excludes other Site 1 cases when this site is supplied.

```python
import duckdb
from phm_case_system import load_system, query_from_measurements

system = load_system("../Datasets/PHM15-prepared/case_system.duckdb")
with duckdb.connect("../Datasets/PHM15-prepared/case_inputs.duckdb", read_only=True) as db:
    query, reason = query_from_measurements(db, 1, "2010-06-07 18:30:00")

if reason:
    print(reason)
else:
    evidence = system.evidence(query, site_id=1)
    print(evidence["class_scores"])
    print(evidence["historical_cases"])
```
